# release_packages

这里放不能通过 Git checkout 切版本的厂商 release 包资产。

它和 `code_assets/` 的区别是：

- `code_assets/` 里的源码项目和工作区，可以按任务需要切 branch / tag / commit
- 这里的 release 包不能切版本，只能使用已取得的目标版本包
- 目标版本不在本目录时，先按任务授权核查已有的可信共享来源；可在本环境接入的，
  核验版本与哈希后接入，不必先交回用户
- 已授权来源中没有，且外部获取超出任务范围或需要新的凭据、权限、许可、版本决策时，
  才停下来交给用户；不要拿相近版本代替

当前目录：

- `m_freertos_sdk/`
  `MCUX SDK / FreeRTOS SDK` 发布压缩包
- `scfw/`
  `i.MX8` 系列 `SCFW` porting kit release 包

使用规则：

1. 先确认目标 SoC / board / BSP 或软件栈要求的 release 包版本
2. 再检查本目录及任务已授权的可信共享来源是否已有对应版本
3. 已有就核验版本与哈希后使用；接入形式按消费端契约选择，不预设链接或复制。
   共享原件保持只读；需要隔离副本时只复制必要输入，不覆盖已有对象。消费端若会
   解析并限制路径在自身目录内，不能放跨根链接，应使用独立普通文件副本。
4. 已授权来源中确实没有时，按任务范围、来源可信度和许可决定是否获取；只有确实
   存在凭据、权限、许可或版本决策缺口时才交给用户，不要用相近版本代替
5. 解压、修改、编译或生成输出，放到 `../work/<case>/`，不要在这里原地污染 release 包

这里不负责：

- 选择最终编译对象
- 承担源码项目的 Git ref 管理
- 记录 case 级构建产物

这些分别交给 `compile_targets/`、`code_assets/` 和 `work/<case>/`。
